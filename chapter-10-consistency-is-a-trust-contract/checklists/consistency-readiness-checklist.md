# Consistency Readiness Checklist

Before releasing a consistency-sensitive capability, confirm:

- User promise is explicit
- Commitment point is identified
- Semantic states are defined
- System of record is known
- Allowed drift is defined
- Actionability rule exists
- Evidence gate exists
- Conflict handling exists
- Compensation path exists
- Decision replay exists
- AI responses are tied to admissible evidence
- UI and API language matches real state transitions
- High-risk decisions have replayable proof
