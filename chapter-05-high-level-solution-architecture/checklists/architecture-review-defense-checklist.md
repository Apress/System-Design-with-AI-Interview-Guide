# Architecture Review Defense Checklist

When defending your high-level design, be ready to explain:

- Why the architecture is not over-engineered
- Which complexity is necessary
- Which complexity is intentionally deferred
- Which capabilities require separate ownership
- Which data needs clear system-of-record control
- Which parts can start as a modular monolith
- Which parts should be separated early
- Which failures are most dangerous
- How the design supports scale
- How the design supports recovery
- How the design controls AI authority
- Which decision you would revisit as traffic grows
