# Architecture View Checklist

Use multiple views when one diagram becomes crowded.

Recommended views:

- Context view
- Service/container view
- Data ownership view
- Runtime sequence view
- Event flow view
- Failure/degradation view
- Security/trust boundary view
- AI evidence and replay view

Each view should answer one clear question.

Avoid:

- Mixing all details into one diagram
- Showing databases without ownership
- Showing AI components without authority boundaries
- Showing queues without explaining why
- Showing services without business capabilities
